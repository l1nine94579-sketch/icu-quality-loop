## 二、必被追问的 12 个问题

### 1. 这个系统解决什么问题？
ICU 每月要向质控中心上报一批指标。痛点不是"算不出来"，而是**算出来没人认**：
分子分母说不清、数据改过对不上、退回了不知道为什么。所以我把重点放在「口径可追溯 + 状态可回放」，而不是堆功能。

### 2. 为什么分四层？直接写 SQL 查不行吗？
直接写会出两个问题：规则（KDIGO）和口径（质控指标）耦合在一起，改一个阈值要动十几条 SQL；
而且每条 SQL 都要重写一遍分期逻辑，必然写歪。
分层后：规则只在 `engine.ts`，口径只在 `indicators.ts`，一层一层都能单测。

### 3. AKI 分期具体怎么算的？
KDIGO 2012，两条路径取最高：肌酐（≥1.5× 基线、48h 内绝对升高 ≥0.3、≥2×、≥3× 或 ≥4.0 mg/dL 或启动 RRT）
与尿量（<0.5 mL/kg/h 持续 6h / 12h，<0.3 持续 24h）。
基线取入科后首份肌酐——这是简化，真实场景应取入院前 7 天基线，我在 README 里写明了这个取舍。

### 4. 为什么缺数据不猜？
柏林定义需要 PaO₂、FiO₂、PEEP 三个前提。缺一个还给分度，医生会当成真的。
所以返回 `insufficient` 并在界面上标"数据不足"，同时把它算进「分层完成率」的缺口里——
**不猜，但也不放过**。

### 5. 指标口径为什么要存 SQL 而不是写死在代码里？
两个原因：① 质控口径每年会调，存库可以带着版本走审批；② SQL 本身就是最好的文档，
面试官/质控科可以直接看分子分母怎么写的。界面里我把 SQL 原样展示出来了。

### 6. "冻结快照"是什么意思？
提交报告的那一刻，把每项指标的分子、分母、命中患者 ID 列表序列化进 `qc_reports.snapshot`。
之后数据库怎么变，上报的数字不变；同时提供"当前重算 vs 冻结值"的差异表，
如果差异大，说明有人改了原始数据，这正是审计要抓的。

### 7. 退回为什么版本号 +1？
因为退回意味着"口径或说明需要改"，新的提交是一份新承诺。
版本号是审计的主键线索：v1 被退回、v2 通过，能对应到两次不同的快照。

### 8. Agent 为什么不让它直接查库？
三个理由：幻觉、越权、无法复盘。
工具是白名单，参数有 schema，返回结构固定；每次调用记录 args 与 observation，前端摊开给医生看。
模型就算想编，也只能编"解释"，编不出一个不存在的患者。

### 9. 没有模型 Key 的时候它怎么工作？
确定性规划器：问题 → 意图（患者 / 指标 / 波动 / 草稿）→ 工具序列 → 模板化结论。
轨迹结构和 LLM 路径完全一致，所以演示不依赖网络，也不会因为模型抽风翻车。

### 10. 医疗 AI 的边界你怎么看？
三条：**可解释**（结论要能回到具体数值）、**可拒绝**（数据不足就说不确定）、**人负责**（写操作必须人工确认）。
这个作品里分别对应：判据表、`insufficient` 分支、HITL 采纳。

### 11. 哪些是你写的？AI 帮了多少？
诚实回答：AI 编程工具参与了实现（这本来就是岗位要求的能力），
但需求裁剪、数据模型、状态机规则、口径定义、Agent 的权限边界是我定的；
每一处都能打开代码解释为什么这么写——这也是我把判据、SQL、审计都做成界面的原因。

### 12. 如果给你更多时间，先做什么？
① 口径版本管理（改口径要审批，报告要标口径版本）；
② 报告导出 PDF 与质控中心接口对接；
③ 把 `rebuild` 做成可回放批处理，支持"某天数据修正后重算影响面"。
