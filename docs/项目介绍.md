# 项目介绍：重症质控闭环工作台

**一句话**：把 ICU 月度质控从「护士填表、质控员算数、主任签字」做成一条可追溯的线上闭环——
数据怎么来的、指标怎么算的、谁在什么时候改了什么，每一步都能点开验证。

- 在线仓库：https://github.com/l1nine94579-sketch/icu-quality-loop
- 规模：67 个文件 / 约 6,100 行 TypeScript / 58 例合成患者 / 5 次提交
- 技术栈：Next.js 15（App Router）+ TypeScript + Node 24 内置 SQLite，零外部数据库依赖

---

## 一、为什么做这个

目标岗位要求三件事：多角色多环节审批、填报与统计口径可追溯、真实的 AI 应用（Agent）设计。
我没有做一个"什么都有"的 CRUD 演示，而是把这三件事各做了一条**能被现场验证**的链路，
范围参考了一份真实的 ICU 系统架构文档（4+1 视图、19 项质控指标、AKI/ARDS 专病规则），
但只保留能力域，砍掉了微服务拆解——那不是个人作品该有的体量。

---

## 二、我负责的部分

### 1. 需求裁剪与领域建模（`db/schema.sql`、`lib/features.ts`）

把系统切成四层，每层只做一件事：

```
原始数据（observations / care_events）
   ↓ 规则引擎（KDIGO、柏林定义）
派生层（patient_metrics，每个患者一行 + 判据 JSON）
   ↓ 指标口径（可审阅的 SQL）
报告层（状态机 + 冻结快照 + 审计）
```

**关键决策**：规则会变、口径也会变，两者不能耦合。KDIGO 阈值调整只动 `engine.ts`，
质控口径调整只动一条 SQL，报告模板不用动。这个分层是后面所有功能能快速加出来的原因。

### 2. 临床规则引擎（`lib/engine.ts`）

- AKI：KDIGO 2012，肌酐倍率（1.5/2.0/3.0×）、48h 绝对升高 ≥0.3 mg/dL、尿量窗口（6/12/24h）、RRT，取最高分期；
- ARDS：柏林定义，P/F ≤300 且 PEEP ≥5；
- **缺数据不猜**：PaO₂ / FiO₂ / PEEP 任一缺失直接返回 `insufficient`，不做缺省推定。

输出不是"分期=2"，而是"分期=2 + 8 条判据（实测值/阈值/是否命中）"。
界面把未命中的判据也列出来（默认折叠），因为医生要看的恰恰是"差多少"。

### 3. 指标口径与报告状态机（`lib/indicators.ts`、`lib/reports.ts`）

7 项指标，每项 = 一段可读 SQL + 一句人话公式 + 目标值 + 方向（越高/越低/仅参考）。
分子分母都在患者粒度产出，所以任意一个百分比都能下钻到具体患者和原始事件。

报告状态机：`填报中 → 待审核 → 已通过 → 已上报`，退回则 `已退回` 且版本号 +1。
提交时**冻结快照**（分子、分母、命中患者 ID 一起序列化），之后数据再变也不改写已上报的数字，
同时提供"冻结值 vs 当前重算"的差异表——差异本身就是审计线索。

### 4. 权限体系（`lib/permissions.ts`）

代码里没有 `if (role === 'qc')`，只有 `can(role, capability)`：11 项能力 × 4 个角色。
三道防线：导航按能力过滤 → 页面首行 `assertCan` → Server Action / API 再校验一次。
护士提交报告、质控员自审自批都会抛 `PermissionError`，而且有专门的测试覆盖。

### 5. 临床 Agent（`lib/agent.ts`）

9 个只读工具（患者档案、KDIGO 复算、柏林复算、指标看板、缺口定位、单项波动解释、报告草稿、审计轨迹等）。
三条硬约束：模型不能直接查库（只能走工具）；每次调用落库可复盘；写操作必须人工确认（HITL）。
两种引擎共用一套轨迹结构：配了 Key 走 function calling，没配走确定性规划器——**断网也能演示**。

### 6. 数据补录闭环（`lib/entry.ts`）

唯一允许"改历史数据"的入口，所以三件事绑死：落库 → 重算该患者 → 前后各算一次指标。
护士补一条 DVT 预防，页面直接告诉你「DVT 预防措施落实率 85.0% → 90.0%」；
如果该周期已提交，还会提示「报告已冻结，差异可在报告页对比」。

## 三、遇到的问题与解决

| # | 问题 | 怎么定位 | 怎么解决 | 结果 |
|---|---|---|---|---|
| 1 | 参考架构文档是 13MB 的 Word 97 二进制 `.doc`，Word 自动化调用直接挂死（"Word 未能引发事件"），机器上又没有 LibreOffice | 用 COM 重试 3 次均超时；文件头是 `D0CF11E0`，确认是 OLE2 复合文档 | 自己写了 OLE2 容器 + Word 97 FIB/CLX 分片表解析器（`_ref/doc_extract.py`），按 piece table 还原正文 | 提取出 4.6 万字、1094 行，拿到了 19 项质控指标与专病规则的原始定义 |
| 2 | 环境没有 Docker 也没有 PostgreSQL，装不了数据库 | 逐一探测 `docker`/`psql` 均缺失 | 用 Node 24 内置 `node:sqlite`，表结构写成 Postgres 兼容（枚举用 CHECK、时间用 ISO 文本），换库只改驱动 | 一条命令跑起来，零外部依赖 |
| 3 | 首页 500：`Only plain objects can be passed to Client Components` | 堆栈指向 layout 传参 | `node:sqlite` 返回的行是 null 原型对象，React 不允许跨 RSC 边界；统一用 `{...row}` 转成普通对象 | 所有页面恢复，且这个转换只有一处，不会漏 |
| 4 | 角色权限形同虚设：只在界面上藏了按钮，改 URL 或直接构造请求就能越权 | 自查发现 `submitReport` 内部没有任何角色判断 | 抽出能力矩阵 + `assertCan`，状态机入口、Server Action、API 三处都加断言；导航按能力过滤，无权限页落 403 | 护士访问 `/audit` 得 403，医生提交报告抛 `PermissionError`，均有测试 |
| 5 | 指标达标判定写反：AKI 发生率明明"越低越好"，却按"越高越好"算达标，页面显示 27.8% 未达标 | 截图核对时发现数字与目标方向矛盾 | 指标定义加 `direction` 字段（up/down/info），达标判定与环比涨跌配色都跟着方向走 | 发生率 27.8%（≤35%）正确显示为达标 |
| 6 | 补录数据后既要反映到指标，又绝不能改写已上报的数字 | 需求冲突：实时重算 vs 历史冻结 | 补录只重算派生层与实时指标，冻结快照保持不动；报告页对比"冻结值 vs 当前重算" | 实测补录后 9 月 DVT 从 85.0% 变 90.0%，报告显示"已发生变化"，原上报值不变 |
| 7 | 导出的 CSV 用 Excel 打开中文全是乱码 | 无 BOM 的 UTF-8 被按 GBK 解析 | 写入 `\ufeff` BOM，并用 RFC 5987 处理中文文件名 | Excel 双击直接正常显示 |
| 8 | 受限环境里测试和构建跑不起来（子进程被拦截，`spawn EPERM`） | 逐个命令试：`node --test` 会 fork、`tsx` 依赖 esbuild 会 spawn | 改成 `tsc` 预编译到 `.build/`，再 `node` 直接执行测试文件；构建单独放行 | 20 个用例可在任何环境稳定复跑 |

## 四、验证方式

我按"能不能被第三方复现"来验收，而不是"我这里能点开"。

### 1. 自动化测试：20 个用例，全绿

| 文件 | 数量 | 覆盖什么 |
|---|---|---|
| `engine.test.ts` | 9 | AKI 各分期、尿量窗口、数据不足、ARDS 分度与 PEEP 前提 |
| `permissions.test.ts` | 4 | 权限矩阵；护士越权提交、质控员自审自批均被拒 |
| `entry.test.ts` | 4 | 补录→重算→指标上升→审计留痕；越权补录；数值越界；补肌酐推高分期 |
| `flow.test.ts` | 3 | 分子分母自洽、退回后版本号递增、提交校验阻断 |

### 2. 端到端：干净检出能不能跑

把仓库打包成 zip、解压到空目录（无 `node_modules`、无数据库、无构建产物），完整走一遍：

```
npm ci        → 28 个包，23 秒，lock 与 package.json 一致
npm run seed  → 生成 58 例患者（固定种子，指标与开发环境逐位相同）
npm run build → 通过
next start    → /、/patients、/reports/2026-10、/indicators、/audit、CSV 导出 全部 200
```

同一次验证里还确认了：护士访问 `/audit` 落到权限页；质控员调 `/api/agent` 返回 200 且 `engine: rules`。

### 3. 业务自洽：数字能不能对上

- 任意指标点"下钻"，分子分母与患者列表逐条对得上（命中/未命中分组，附证据字段）；
- 分子 ÷ 分母 = 页面百分比（测试里断言到小数点后 6 位）；
- 提交后冻结快照与当前重算可对比，改过数据会显式标"已发生变化"；
- 补录实测：85.0% → 90.0%，且审计里同时留下 `event_added` 与前后指标值。

### 4. 工程验证

- `tsc --noEmit` 0 错误；`next build` 通过；
- 断网可演示（Agent 走确定性规划器）；
- 403 / 404 页面虽有（Next 流式渲染下状态码为 200，已写入 README 的已知边界）。

---

## 五、已知边界

1. 没有对接真实 LIS / 设备网关 / 单点登录，接入口设计成 `observations`、`care_events` 两张表；
2. 权限是 4 角色的固定矩阵，没有做按科室自定义角色（RBAC 表）；
3. 补录只能新增，不能撤销或批量导入——真实场景需要 Excel 导入与错录撤回。

---

## 六、面试时怎么讲（3 分钟）

1. **一句话**：重症质控的闭环系统，重点是"每个数字都能点开、每个动作都留痕"。
2. **讲分层**：原始数据 → 规则派生 → 指标口径 → 报告，四层解耦，规则和口径互不牵连。
3. **讲一个难点**：Word 文档打不开，最后自己解析 OLE2 二进制把正文抠出来——说明遇到工具链缺口时的处理方式。
4. **讲验证**：20 个用例 + 干净检出跑通 + 越权测试，而不是"我本地能跑"。
5. **收尾**：AI 编程工具参与了实现，但规则、口径、权限边界和验收标准是我定的，每一条都能打开代码解释。

### 高频追问准备

- **为什么不用 Postgres？** 演示要一键跑；表结构兼容，换库只改驱动。
- **Agent 会不会瞎编？** 不能直接查库，只能走 9 个工具；轨迹全落库；写操作要人点确认。
- **数据是假的怎么证明不是玩具？** 规则、口径、状态机都是真的；数据量小是刻意的，方便现场随便挑一行验算。
- **并发怎么办？** 目前靠状态机校验（第二次审核会被拒），没有做版本号乐观锁——这是已知的下一步。
